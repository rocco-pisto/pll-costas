# PLL Costas

FPGA implementation of a **Costas-loop PLL** (carrier phase/frequency
recovery) on an Intel/Altera Cyclone IV E. The design is built bottom-up:
each block is written in VHDL, checked against a Python model in a
cocotb + Questa testbench, then integrated in the top level and tested on the
board.

> **Status: v0.1.0** (first version tested on the board). The NCO is done; the
> Costas loop itself (mixer, phase detector, loop filter) is not started yet.
> Today the top level runs a fixed 1 Hz NCO and shows its sine on the 8 LEDs.

## Goal

A Costas loop locks a local oscillator to a suppressed-carrier signal
(e.g. BPSK):

```
            ┌──► x ──► LPF ──► I ─┐
 input ─────┤    ▲                ├──► phase detector (I·Q) ──► loop filter ──┐
            └──► x ──► LPF ──► Q ─┘                                          │
                 ▲ cos/sin                                                   │
                 └──────────────── NCO ◄──── freq_i (centre + correction) ◄──┘
```

Blocks still to do: mixers, low-pass filters, phase detector, loop filter
(PI) and the input path. Open questions (decide before designing them):

- Where the input signal comes from (on-board ADC, GPIO, internally
  generated test signal), and at what sample rate.
- Modulation (BPSK assumed), carrier frequency range, required loop bandwidth
  and lock range.
- How lock status and the recovered phase/frequency are observed (LEDs, UART,
  SignalTap).

## Current design (v0.1.0)

```
clk_0 ─► reset_pulse ─► rst_pulse ──► pll_200.areset
clk_0 ─► pll_200 ─► clk_200 (4 × 50 MHz)        pll_200.locked
rst_n, rst_pulse            ─► synchronizer @clk_0   ─► rst_0_n   (unused for now)
rst_n, rst_pulse, locked    ─► synchronizer @clk_200 ─► rst_200_n
clk_200: nco (freq_i = 1 Hz) ─► sin ─► offset binary (3 MSB) ─► decoder ─► led_0..7
```

Worst setup slack at 200 MHz (Slow 85C) is +0.88 ns (Fmax ≈ 243 MHz),
about 216 LEs.

## Conventions

The full rules are in [CLAUDE.md](CLAUDE.md). In short:

- **VHDL:** doxygen comments (`--!`) on every entity, generic and port. Ports
  end in `_i`/`_o`, and the reset is `rst_n` (synchronous, active low).
  Fixed-point formats are written as Qm.n or UQm.n in the comments.
  Instance labels are `component_<name>`, and component declarations are used
  rather than direct entity instantiation.
- **Models:** simple numpy models in `mod_<block>.py`. They match the RTL
  numerically (integer arithmetic) but don't copy its structure.
- **Tests:** cocotb + Questa. `tb_run.py` compiles and runs, `tb_<block>.py`
  holds the test. Every test applies a reset, compares against the model
  (≤ 1 LSB) and, where it makes sense, against an ideal float reference.
  Plots go in `test/<dir>/results/` (git-ignored).
- **Before designing a new block:** ask for the full specification and for a
  reference design or model. Don't make non-trivial architecture decisions
  alone.

## Gotchas

- **Quartus Prime Standard cannot synthesize `ieee.fixed_pkg`.** Use
  `work.ufixed_pkg` / `work.sfixed_pkg`, or `numeric_std` plus `math_real`
  (constants only).
  Questa accepts `ieee.fixed_pkg`, so a passing simulation does not mean it
  will synthesize.
- **Quartus Prime Standard's `math_real.round()` is wrong above 2³¹**
  (it leaves the value unrounded), so a constant computed with it can be off
  by one LSB with no warning. `integer(real)` and `round()` on smaller values
  are fine. `to_ufixed(real)` / `to_sfixed(real)` go through `integer`, so they accept
  only raw values (value / LSB) below 2³¹ and stop with an assert above that.
- **Quartus Prime Standard lacks the VHDL-2008 built-ins `maximum`/`minimum`.**
  `ufixed_pkg` declares its own `maximum`/`minimum(integer, integer)` (only
  there, so using both packages is not ambiguous). With `use work.ufixed_pkg.all`
  the code reads like VHDL-2008, and Questa prefers
  the explicit declaration over its built-in. To check that new VHDL
  synthesizes, run `quartus_map` on a small scratch project with that
  entity as the top level.
- **The project is VHDL-2008** (`VHDL_INPUT_VERSION VHDL_2008` in the QSF and
  `-2008` in the testbenches).
- **The ROM IP opens its `.mif` relative to the simulator's working
  directory.** Testbenches that use `sincos` copy the MIF files into
  `sim_build/` (see `_stage_mif_files` in `tb_run.py`).
- **Questa only allows one session at a time.** Close the GUI before running
  the testbenches.
- **Clocks that aren't a whole number of ns** (200 MHz = 5 ns needs a 2.5 ns
  half period) need `test_args=["-t", "ps"]` in `runner.test`. cocotb's
  `timescale` option doesn't reach vsim for this setup.
- **Sample outputs with `await RisingEdge` followed by `await ReadOnly()`** to
  get each cycle's settled register values.
- **Read pipeline depths from the DUT** rather than hard-coding them, e.g.
  `dut.component_sincos.NPIPE.value`.
- **When adding a pipeline stage,** delay every signal that is used together
  (data, sign, interpolation factor, valid) by the same number of clocks. The
  sincos testbench checks this by comparing single-shot and streaming results.
